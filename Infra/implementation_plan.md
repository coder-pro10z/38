# Azure Infra (JD) — 20-Slide JSON Structure Plan

## Field Role Definition

| Field | Role | Content Rule |
|---|---|---|
| `definition` | Theory | One sentence — **what the technology is**. No how. |
| `why_it_matters` | Theory | One sentence — **business/operational impact**. Risk if misconfigured. |
| `content_theory` | Theory | "Here is a breakdown..." section. Uses `Best For:` / `Requirements:` / `Core Azure Resources:` labels. Explains **concepts, types, comparisons** — zero CLI/Terraform. |
| `content_implementation` | Implementation | Opens with a **risk/gotcha statement**. Then `Key Deployment Considerations:` with named checklist items. Explains **how to build it**. |
| `key_commands` | Implementation | Terraform HCL blocks or Azure CLI commands with description. |
| `architecture_flow` | Implementation | Step-by-step traffic/data flow. Used when implementation is a **flow design** not code. |
| `comparisons` | Theory | Side-by-side concept comparison. Stays in the "what" space. |
| `trade_offs` | Implementation | Design decision table — SKU, tier, strategy choices. |
| `interactive_html` | Canvas | Self-contained HTML+JS+CSS tool. One per slide. Each is unique. |
| `interview_kill_shot` | Both | One-sentence synthesis. The last 10-second answer. |

---

## Content Separation Rule

```
content_theory       → WHAT it is + TYPES/COMPONENTS + "Best For / Requirements / Core Resources"
                        Zero Terraform. Zero CLI. Zero portal steps.

content_implementation → RISK/GOTCHA statement first
                          "Key Deployment Considerations:" checklist
                          HOW to build it — sizing, SKU decisions, config steps
                          Leads into key_commands or architecture_flow
```
